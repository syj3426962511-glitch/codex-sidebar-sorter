# 未来版本适配方案

## 目标

排序工具拥有独立的安装目录、运行时、配置、托盘和后台进程。Codex 使用原有启动入口和更新流程。排序结果通过已授权且已验证的接口同步到 Codex 原侧边栏。

未来适配采用能力协商、独立适配器、适配器更新和云端回归。接口兼容的新版本沿用已有适配器。接口、权限或操作语义发生变化时，更新相应适配器并完成真实客户端验收。

## 六项设计

| 设计 | 具体执行 |
| --- | --- |
| 独立运行 | 使用自带运行时和独立配置。关窗保留后台，Codex 关闭后后台等待，下次打开时重新连接 |
| 动态发现 | 每次连接重新发现当前客户端和端点，记录客户端版本、账户、主机和连接代次 |
| 能力协商 | 读取操作目录及可用参数结构，核对所需参数、枚举、返回字段、完整分页及授权状态 |
| 分范围适配 | 项目、项目内对话、置顶、自定义分区和最近对话分别判断能力，批次开始前检查全部所需操作 |
| 独立更新 | 客户端接口变化后，下载发布者签名的适配包，在工具自己的目录验证和启用，保留上一份可用适配包 |
| 云端回归 | 新版本发布后验证真实排序、关闭重开、更新替换、后台持续运行和资源占用，公开具体版本结果 |

## 更新时的行为

1. Codex 退出或更新使连接断开，工具保留排序规则并进入等待状态。
2. Codex 重新打开，工具发现新端点，重新核对能力、账户与项目归属。
3. 接口契约兼容时，读取最新列表，计算差异并继续同步。
4. 已发布匹配的适配包时，完成签名验证、只读探测和原子切换，再继续同步。
5. 契约或权限仍待适配时，显示具体待适配范围，保留用户规则，等待有效适配或授权。

中断后的排序从客户端实际保存的状态重新计算。完成状态以回读顺序为准。已有接口缺少整批事务时，按实际成功的操作记录进度，重试前重新读取归属和顺序。

## 适配器的内容

适配包保存操作映射、参数与返回结构、能力规则、无障碍控件定位规则。版本号用于记录已验收范围，适配选择以实际接口契约为主。新增可选字段且既有语义保持时，可以继续沿用适配器。

新的传输协议或可执行逻辑通过工具自身升级交付。日常接口映射变化通过数据型适配包交付。工具每天、遇到新契约时或用户手动检查时查询发布渠道，网络中断时继续使用已缓存的匹配版本。

Windows UI Automation、macOS 辅助功能和 Linux AT-SPI 按平台分别验证。后台操作要求目标唯一、归属明确、顺序可回读，并核验前台窗口和鼠标位置。macOS 当前已通过权限与控件读取验证，登录后的后台排序继续待验收。

## 旧版本覆盖

按真实的接口、授权和数据结构划分历史版本。每类接口使用对应适配器并安排代表性旧客户端实测。当前历史读取已覆盖六类结构，包括名称字段、秒与毫秒时间、项目映射、代理记录和附属对话过滤。

历史数据库查询采用只读方式。客户端排序持久化通过其已授权的排序操作执行。老版本缺少排序接口时，需要对应平台的无障碍排序通过验收，才能列入原侧边栏同步支持范围。

## 验收顺序

1. Codex 普通启动、关窗、完整退出和重开。
2. Codex 旧版更新为目标版后的冷启动，以及排序后台的独立存活。
3. 登录后七种排序在原侧边栏的保存和显示。
4. 新增、改名、删除、跨项目移动、手动调整和批次中断后的同步。
5. 安装路径选择、自带运行时、工具覆盖升级、偏好保留、卸载与低占用。
6. 适配包签名、断网缓存、中断下载、切换和回退。

功能、安装和客户端操作测试继续全部使用云主机。每项回执记录客户端、工具、适配器的具体版本和测试范围。
